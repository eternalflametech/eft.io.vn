# Contributing to Eternal Flame Tech (EFT)

First off, thank you for considering contributing to the **Eternal Flame Tech (EFT)** project! Whether you are a club member, an alumnus, or an open-source contributor, your help makes this project better for everyone.

---

## 📋 Code of Conduct

By participating in this project, you agree to abide by our [Code of Conduct](CODE_OF_CONDUCT.md). Please treat all contributors with respect and professionalism.

---

## 🛠️ Development Workflow

### 1. Fork & Branch Structure

- Always branch off from the latest `main` branch.
- Use descriptive branch names adhering to standard conventions:
  - `feature/<feature-name>` for new features (e.g., `feature/sliding-navbar`)
  - `fix/<bug-name>` for bug fixes (e.g., `fix/tally-iframe-modal`)
  - `refactor/<module-name>` for code restructurings
  - `docs/<topic>` for documentation updates

```bash
git checkout main
git pull origin main
git checkout -b feature/your-feature-name
```

### 2. Local Environment Setup

1. Make sure you are using **Node.js LTS (v18+)** and **npm (v9+)**.
2. Install dependencies:
   ```bash
   npm install
   ```
3. Run the development environment:
   ```bash
   npm run dev
   ```
   This will concurrently watch Tailwind CSS changes and serve the static files on `http://localhost:3000`.

### 3. Modifying Styles & Scripts

- **Tailwind CSS**:
  - Write custom styles inside `src/input.css` using Tailwind `@apply` or utilities where appropriate.
  - Never edit `css/style.css` directly — it is generated by `npm run build`.
  - Always run `npm run build` before committing to ensure `css/style.css` is up to date.

- **Modular JavaScript (`js/modules/`)**:
  - Keep modules self-contained within the `window.EFT` universal namespace.
  - Ensure all features operate reliably on both HTTP servers (`http://`) and direct file loading (`file:///`).
  - Do not introduce heavy runtime dependencies unless thoroughly discussed.

## 📝 Commit Conventions

We follow the [Conventional Commits](https://www.conventionalcommits.org/) specification:

```text
<type>(<optional scope>): <description in imperative mood>
```

Common types:
- `feat`: A new feature (e.g., `feat: add smooth sliding switch pill indicator to desktop navbar`)
- `fix`: A bug fix (e.g., `fix: load Tally iframe directly and remove animate-pulse from modal title dot`)
- `refactor`: Code changes that neither fix a bug nor add a feature
- `style`: Changes that do not affect the meaning of the code (formatting, CSS tweaks)
- `docs`: Documentation changes (`README.md`, `CONTRIBUTING.md`, etc.)
- `chore`: Maintenance tasks (dependency updates, configuration changes)

---

## 🚀 Pull Request Checklist

Before opening a Pull Request, please ensure:

1. [ ] The application compiles cleanly with `npm run build`.
2. [ ] All responsive views (desktop, tablet, and mobile) render correctly.
3. [ ] No console errors or unresolved asset paths.
4. [ ] Commit messages follow the Conventional Commits format.
5. [ ] The branch is rebased or up-to-date with `origin/main`.

When your PR is submitted, GitHub Actions will automatically verify that the build succeeds. Maintainers will review and merge your changes into `main`, which automatically deploys to [eft.io.vn](https://eft.io.vn).
